## Step 2｜数据理解（EDA）

```powershell
python step2_explore.py
```

**预期输出**（关键几行）：
```
【pollutions】共 6 种取值：

    ...

    (NaN)                  15,229 行

> 🔴 **重点看这里！** 这就是**陷阱 2 的铁证**：
> - `pollutions` 里装的是"优/良"（质量描述），不是污染物
> - `quality` 里装的是"PM25/PM10"（污染物），不是质量
> - **两列完全对调了**
>
> 另外注意：`quality` 的 NaN 数（15,229）**正好等于** `pollutions` 里"优"的数量 —— 因为空气为"优"时不存在首要污染物。

打开 `output/report_eda.txt`，**回答最后的 5 道思考题**。答不上来的地方就是你需要补的。

```

## Step 8｜Spark MLlib 建模（可选，耗时较长）

> ⏱ **完整跑完约 25–30 分钟**（本地单机）。
> 如果只是想验证系统能不能跑，**可以跳过这一步** —— 它不影响后面的 MySQL 和 Web 部分。

```powershell
python step8_mllib.py
```

**预期输出**：
```
  读取 5,715,643 行，耗时 16.7 秒
  清洗后 5,533,758 行（移除 181,885 行重复/无效），耗时 51.7 秒
  特征构造完成：5,518,446 行，耗时 93.2 秒
  城市数：319

  【持续性基线】直接把当前 AQI 当作 24 小时后的值：
    RMSE = 33.04   MAE = 18.85   R2 = 0.4305

  GBT 回归训练耗时：231.4 秒
    RMSE = 27.61   MAE = 16.42   R2 = 0.6023
    -> 相比持续性基线 MAE 降低 12.9%
       [OK] 模型优于基线

  【带类别权重】  准确率 = 0.8509   AUC = 0.9248   污染天召回率 = 83.8%
  【不带权重】    准确率 = 0.9018   AUC = 0.9233   污染天召回率 = 56.1%
```

> 🔴 **这一步最关键的理解**：
> **不带权重的模型准确率更高（0.90 vs 0.85），却漏掉了 43.9% 的污染天（169,494 条）。**
> 预警系统的代价不对称 —— 误报可控，漏报代价高得多。**宁可多报，不能漏报。**
>
> 这就是《设计方案》里"通过类别权重调整应对类别分布不平衡"的意义。

> ⚠️ **如果只跑一次，请注意时间**：脚本会依次做「数据读取 → 清洗 → 特征构造 →
> 回归训练 → 交叉验证（约 10 分钟）→ 分类训练（约 10 分钟）→ 聚类」。
> **中途不要关窗口**，日志会实时写入 `output/report_mllib.txt`，可以另开窗口看进度。

# 🔧 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `RAW_DIR ... (不存在!)` | 目录层级算错 | 检查 `config.py` 的 `dirname` 层数 |
| `JAVA_HOME ... 未找到` | 便携版 JDK 被删了 | 重新下载 Temurin JDK 17 解压到 `.tools\jdk17\` |
| `ClassNotFoundException: SparkSubmit` | SPARK_HOME 指向了中文路径 | 检查 `.tools\spark42` 联接是否还在 |
| `Python worker failed to connect back` | driver 绑到了网卡 IP | `step6_spark.py` 的 `setup_env()` 已处理，重启即可 |
| `pymysql` 连接失败 | MySQL 没启动 | 先运行 `run_mysql.ps1` |
| 页面显示"加载失败" | 后端没起 / 数据没导 | 按顺序：MySQL → step7 → run_web |
| 图表中文变方框 | matplotlib 没找到中文字体 | `step4_analyze.py` 的 `setup_chinese_font()` 已处理 |
| `joblib` 报 ascii 编码错 | 中文路径 + 多进程 | `step5_model.py` 里已设 `n_jobs=1` |
